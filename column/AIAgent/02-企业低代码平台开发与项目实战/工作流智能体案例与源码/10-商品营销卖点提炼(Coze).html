3.10 - Coze 案例：商品营销卖点提炼 ​

本案例概要 ​

本案例是 Coze 教程中结构最复杂的一例：采用 1 个 Agent + 5 个工作流 的混合架构，实现从「设置产品信息」→「提炼卖点」→「卖点转买点」→「生成小红书文案 / 短视频脚本」的完整营销链路，并支持按需单独执行某一环节。

使用的平台能力（无外部插件） ​

能力/节点类型作用说明
开始 / 结束工作流入口与出口；开始节点可接收 BOT_USER_INPUT 及与数据表字段同名的参数（如 name、description），便于 Agent 从对话或数据库补全入参。
输出向用户逐条或一次性输出提示/结果，流式开关控制输出方式。
问答多轮交互核心：支持「直接回答」（封装为 USER_RESPONSE）或「选项回答」（按选项走不同分支，相当于分支 + 意图识别）。
变量赋值将节点结果写入用户变量（产品名称、产品功能、三类卖点、三类买点等），供本工作流及后续工作流、主流程复用。
代码Python：产品名称长度校验（≤9 字）、随机抽取「营销关键词 / 短视频开头·结尾技巧关键词」等，用于校验与生成多样性。
大模型生成产品一句话描述、通用/独特/保障性卖点、卖点 → 买点转换、小红书文案、短视频分镜脚本；依赖系统提示词约束格式与风格。
选择器根据代码或前序节点输出（如是否检索到热点、名称是否合法）做条件分支。
循环 / 终止循环无限循环内实现「校验不通过则重新提问」或「多轮生成文案/脚本直到用户选择不再生成」。
文本处理字符串拼接与模板，如补充描述拼接、最终汇总卖点/买点/文案/脚本为一份 Markdown。
数据表 + SQL表 product_list 持久化产品名称与描述；SQL 自定义节点写入；Agent 在对话无产品信息时可从该表取最新一条填充工作流入参。
知识库检索知识库「尚硅谷-抖音热点」「尚硅谷-微博热点」「短视频脚本技巧_开头/结尾」「高质量营销文案技巧」为文案/脚本生成提供热点与技巧上下文。
工作流子调用主流程中顺序调用 4 个子工作流；Agent 也可根据用户意图单独调用其中某一个。

五个工作流职责 ​

工作流名称职责概要
set_product_name_and_desc设置/更新产品信息：引导输入或选择示例产品名 → 长度校验（循环+代码+选择器）→ 大模型生成描述 → 满意则写入用户变量，否则补充后拼接再写入 → 写入数据表 → 输出整理后的产品信息。
selling_point_generation生成三类卖点：通用性 / 独特性 / 保障性。每类均为「提示 → 多轮问答（可 AI 代答）→ 大模型生成 → 满意/修改分支 → 写入对应用户变量」。依赖用户变量中的产品名称、产品功能。
selling2buying_point将已有三类卖点转为三类买点（痛点、爽点、痒点、兴奋点、安全点等）。每类为「提示 → 大模型转换 → 满意/补充分支 → 写入对应用户变量」。输入来自用户变量，无需额外参数。
red_book_and_video_script基于用户变量中的买点，多轮生成「小红书文案」或「短视频分镜脚本」。循环内：是否生成 → 热点检索（知识库）→ 是否使用热点 → 随机技巧关键词（代码）→ 技巧检索 → 大模型生成 → 输出；支持多轮直到用户选择不再生成。
主流程（全流程）开始 → set_product_name_and_desc → selling_point_generation → selling2buying_point → red_book_and_video_script → 文本处理（汇总产品+卖点+买点+文案+脚本）→ 结束。

技术要点 ​

  • Agent 调度：通过「人设与回复逻辑」中的自然语言条件（如「只要求设置产品信息」「只要求生成卖点」「只要求卖点转买点」「生成文案或脚本」）决定调用哪一个工作流；全流程一次跑完时按固定顺序调用上述 4 个子工作流。
  • 用户变量贯穿多轮与多工作流：产品名称、产品功能、通用/独特/保障性卖点、通用/独特/保障性买点等均存为用户变量，子工作流通过开始节点或直接引用用户变量获取输入，实现「设置一次、多处使用」。
  • 问答节点分支：大量使用「选项回答」（如满意 / 修改、A/B/其他），由模型判断用户意图并进入不同分支，实现「满意则落库/写变量，否则继续提问或调用大模型补充」。
  • 循环 + 选择器 + 代码：产品名称长度校验用「无限循环 + 代码算长度 + 选择器判断 + 终止循环/重新问答」；文案/脚本生成用「循环内问答是否继续 + 选择器区分小红书/短视频 + 代码随机关键词 + 知识库检索 + 大模型」。
  • 数据表与参数补全：product_list 与开始节点参数名一致（name、description），便于在对话中没有产品信息时，由 Agent 从数据库取最新一条填入工作流，保证「单独生成卖点」等场景可用。
  • 知识库与随机技巧：热点库、文案技巧库、短视频开头/结尾技巧库通过检索注入大模型上下文；代码节点随机选关键词（如「形容外观」「突出价格」等）再检索，使每次生成的文案/脚本角度不同。
  • 结构化输出与格式约束：大模型通过系统提示词约束输出格式（如卖点/买点列表、小红书标题/正文/标签、短视频分镜的时长/画面/台词等），便于后续展示与拼接。

    ↓

3-1.问答节点介绍 ​

创建问答节点

模型用于处理用户输入，根据节点模型的不同，将用户输入封装为变量，或确定下游分支。

提问内容是工作流运行至当前节点时，输出给用户的提示。

问答节点有两种回答方式：

  1. 直接回答

顾名思义，选择这种方式，节点会将用户输入封装在USER_RESPONSE变量中，将提问内容封装在QUESTION_DATA变量中。

  1. 选项回答

这种方式下，问答节点相当于一个分支结构，根据用户回答或选择，工作流将执行不同的分支结构。

其他相当于分支结构的else，当用户输入的回答与任意选项都不匹配时，执行此分支。

import time
import random

async def main(args: Args) -> Output:
    keywords = [
        "形容外观",

        "展示工艺",
        "展示材料/成分",
        "形容功能",

        "突出人群",

        "营造稀缺"
    ]

    # 使用当前时间戳与随机数结合来增加随机性
    base_random = random.random()
    time_seed = int(time.time() * 1000)  # 毫秒级时间戳
    enhanced_random = (base_random + time_seed) % 1

    random_index = int(enhanced_random * len(keywords))
    keyword = keywords[random_index]

    ret: Output = {
        "keyword": keyword
    }

    return ret
